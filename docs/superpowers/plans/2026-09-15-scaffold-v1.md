# Commitment Intelligence Scaffold V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a downloadable, modular Next.js frontend scaffold that demonstrates permission-aware customer commitment intelligence using mock data.

**Architecture:** A frontend-first Next.js app uses typed mock records and pure domain helpers. Permission filtering happens in the domain layer before evidence is assembled into mock answers or traces, preserving the future architecture without inventing a backend.

**Tech Stack:** Next.js 16.3.3, React 19.3.0, TypeScript, Tailwind CSS 4.3, Node.js built-in test runner.

**Spec:** `docs/superpowers/specs/2026-09-15-commitment-intelligence-design.md`

## Global Constraints

- V1 remains frontend-first and mock-data driven.
- Do not add a database, real authentication, connectors, vector search, embeddings, reranking, or LLM integration.
- Unauthorized evidence must be removed before answer/trace assembly.
- Keep feature folders small and domain logic separate from presentation.
